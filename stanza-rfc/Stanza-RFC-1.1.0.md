# Stanza 纯文本任务管理格式规范

**RFC 1 — Stanza Plain-Text Task Management Format**

> **状态：** 草案 (Draft)
> **版本：** 1.1.0
> **日期：** 2026-08-15
> **语言：** 中文 (zh-CN)

---

## 1. 摘要 (Abstract)

Stanza 是一种受 [TODO.txt](http://todotxt.org/) 启发的纯文本任务管理格式。它通过引入**状态区块（State Blocks）**和**段落式任务（Task Paragraphs）**，在保持纯文本完全自由的基础上，提供了更清晰的视觉分层与状态流转能力。名称取自诗歌中的"节"（stanza），呼应其以段落组织任务的结构。

本规范定义了 Stanza 文件的语法、语义及解析规则，旨在实现跨平台、跨工具的一致性与互操作性。

---

## 2. 设计哲学 (Philosophy)

1. **纯文本即全部**：单个纯文本文件，无数据库、无专有格式、无厂商锁定。
2. **状态驱动**：任务的生命周期（DOING / WAIT / DONE / DELETE）通过文件内的物理区块直观呈现。
3. **人类可读优先**：格式服务于人的阅读与手动编辑，其次才是机器解析。
4. **一行一任务，一段一详情**：主行承载结构化元数据，缩进续行承载自由备注（唯一的结构化例外是时间戳行，见 §7.4）。
5. **最小惊讶原则**：与 TODO.txt 保持概念兼容，仅在必要时引入新语法。
6. **无隐式状态**：任务的全部元数据必须显式写在其主行上，不依赖上下文继承。

---

## 3. 术语与约定 (Conventions)

### 3.1 要求级别

本文中的关键词含义如下（参照 RFC 2119）：

- **必须 (MUST)**：绝对要求，不满足即不符合本规范。
- **应当 (SHOULD)**：推荐做法，存在正当理由时可偏离。
- **可以 (MAY)**：可选项，由实现自行决定。

### 3.2 本文术语

| 术语       | 定义                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 空白行     | 不含任何字符，或仅含空格 (`U+0020`) 与制表符 (`U+0009`) 的行         |
| 缩进行     | 第一个字符是空格或制表符的非空白行                                   |
| 无缩进行   | 第一个字符不是空白字符的非空白行                                     |
| 区块标题   | 声明状态区块的专用行，见 §6                                          |
| 任务锚点   | 标志新任务开始的无缩进行                                             |
| 主行       | 任务段落的第一行，承载结构化元数据，见 §7.2                          |
| 续行       | 属于某个任务锚点的缩进行，见 §7.3                                    |
| 时间戳行   | 承载生命周期时间的专用续行，见 §7.4                                  |

---

## 4. 文件格式 (File Format)

- **编码**：必须使用 UTF-8。解析器应当容忍文件开头的 BOM 并将其忽略。
- **换行符**：解析器必须同时接受 LF 与 CRLF；写出文件时应当使用 LF。
- **扩展名**：不作强制要求，推荐使用 `.txt`。工具可以自行约定其他扩展名（如 `.stanza`）。
- **单文件**：一个文件容纳全部状态区块与任务。本规范不定义多文件拆分方式。

---

## 5. 文件结构概览 (Overview)

一个 Stanza 文件由若干**状态区块**顺序组成。每个区块包含若干**任务段落**。一个任务段落由一行**主行**和零至多行**缩进续行**构成。每条无缩进的非空白行都开启一个新任务（换行即分隔）；书写时应当在任务之间保留一个空白行以提高可读性，但解析器不依赖空白行判断任务边界。

```
状态区块
├── 区块标题行
├── 空白行（建议）
├── 任务段落 1
│   ├── 主行（无缩进）
│   └── 续行（缩进，可含空白行）
├── 空白行（建议的视觉分隔）
├── 任务段落 2
│   ├── 主行
│   └── 续行
└── ...
```

## 6. 状态区块 (State Blocks)

### 6.1 语法

状态区块以**区块标题行**开始，独占一行：

```bnf
block_title ::= "#" SP state_name [trailing_ws]
state_name  ::= "DOING" | "WAIT" | "DONE" | "DELETE"
trailing_ws ::= *( SP | TAB )
```

- 区块标题必须位于行首（前面无空白字符）。
- `#` 与状态名之间必须恰好是一个空格。
- 状态名拼写必须与上述四种之一完全一致，但**大小写不敏感**（`# doing`、`# Doing` 均识别为 `DOING` 区块）；拼写有误（如 `# DONIG`）则不识别为区块标题。书写与工具写出时应当使用全大写的规范形式。
- 行尾允许零或多个空白字符，解析器应当容忍。
- 区块标题下建议跟一个空白行再开始任务列表；解析器**不得**依赖该空白行存在。
- 不能整行匹配上述语法的行（如 `# DOING 杂记`、`#TODO`）不是区块标题，按普通无缩进行处理。
- 写入工具应当避免让任务主行以 `#` 开头，以免造成混淆；任务主行尤其不得与任一区块标题（含大小写变体）完全相同（否则无法与区块标题区分）。

### 6.2 语义

| 区块     | 语义                        | 优先级使用            |
| -------- | --------------------------- | --------------------- |
| `DOING`  | 当前正在执行的任务          | 支持 `(A)`–`(Z)` 排序 |
| `WAIT`   | 因外部依赖而阻塞的任务      | 支持 `(A)`–`(Z)` 排序 |
| `DONE`   | 已完成的任务                | **不使用**优先级      |
| `DELETE` | 已废弃/删除的任务（回收站） | **不使用**优先级      |

优先级字母约定 `(A)` 为最高，字母越靠前优先级越高。

### 6.3 空区块

不含任何任务的区块合法。解析器必须保留该区块，以便写入工具向其中添加任务。

### 6.4 多个同状态区块

同一文件内允许出现多个相同状态名的区块。解析器应将它们逻辑合并为同一个状态集合。

## 7. 任务段落 (Task Paragraphs)

### 7.1 边界规则（核心算法）

每条**无缩进的非空白行**都开启一个新任务。解析器逐行处理，规则如下：

1. 遇到**区块标题行** → 开启新区块，当前任务锚点立即结束。
2. 遇到**空白行** → 暂存，其归属待定（见规则 3、4）。
3. 遇到**缩进行**：
   - 若存在当前任务锚点 → 该行为续行；此前暂存的空白行一并计入该任务的备注（**备注内空行**）。
   - 若不存在当前任务锚点 → 该行为孤立续行，解析器应当忽略（可以给出警告），不得报错。
4. 遇到**无缩进行** → 一律视为新任务锚点（无论此前是否有空白行），暂存的空白行丢弃。
5. 文件末尾暂存的空白行忽略。

简言之：**换行即分隔**——任务之间不需要空白行（仅作推荐的视觉分隔）；唯一的例外是空白行后接缩进行时，空白行属于上一个任务的备注内容。

### 7.2 主行 (Header Line)

主行是任务的结构化定义，格式如下：

```bnf
header_line ::= [priority] [date] body
priority    ::= "(" letter ")" SP
letter      ::= "A" | "B" | ... | "Z"
date        ::= 4DIGIT "-" 2DIGIT "-" 2DIGIT SP
body        ::= 1*CHAR            ; 描述主体，可内嵌 project 与 tag
project     ::= boundary "+" name
tag         ::= boundary "#" name
boundary    ::= 行首 | SP | TAB
SP          ::= U+0020
TAB         ::= U+0009
```

**名称字符集**：`name` 由 Unicode 字母、数字、连字符 `-`、下划线 `_` 构成（中日韩等表意文字属于 Unicode 字母，天然受支持）。项目名允许以数字开头；**标签名首字符必须是字母**（因此 `#1`、`#123`、`#2026计划` 不识别为标签，避免与编号冲突）。项目名与标签名大小写敏感；工具在做分组统计时可自行决定是否归一化大小写。

**解析顺序**（必须按此顺序）：

1. 从行首提取可选的优先级（`(A)`–`(Z)`，后跟一个空格）。
2. 提取可选的日期（`YYYY-MM-DD`，后跟一个空格）。
3. 剩余部分为描述主体；从中提取项目（至多一个）与标签（零至多个），提取后将其从描述文本中移除，并归并多余的空白。

#### 7.2.1 优先级（Priority）

- 可选。若存在，必须位于主行最前端，右括号后必须紧跟一个空格。
- 仅在 `DOING` 和 `WAIT` 区块中有排序意义（`(A)` 最高）。
- 为保证解析行为一致，解析器在所有区块中均按同一语法识别优先级；但 `DONE`、`DELETE` 区块中的优先级**无任何语义**，不得用于排序或展示。写入工具在任务进入 `DONE`/`DELETE` 时应当移除优先级前缀（见 §9）。
- 同一区块内不建议重复使用同一优先级字母；解析器无需强制唯一。

#### 7.2.2 日期（Date）

- 可选。若存在，必须紧跟在优先级（及空格）之后，或位于主行最前端（无优先级时）。
- 只有严格符合 `YYYY-MM-DD`（ISO 8601）的写法才占据日期位。其他写法（如 `8/7`、`8月7日`）不识别为日期，仅作为描述文本的一部分，解析器不得报错。
- 语义：任务的**截止日期（due date）**。主行日期是文件中唯一的**裸日期**（不带关键字的日期）；创建时间与完成时间以时间戳行的形式记录在续行中（见 §7.4）。
- 任务进入 `DONE` 后，截止日期作为历史信息保留，实际完成时间按 §9 约定记录在续行。工具在区块内排序时，可以将截止日期作为优先级之后的第二排序键（较早的在前）。

#### 7.2.3 描述（Description）

- 任务的纯文本核心内容，应当非空。为空时（如主行只剩元数据）解析器不得报错。
- 不得包含换行；多行内容（详细说明、执行步骤等）通过缩进续行（§7.3）承载。

#### 7.2.4 项目（Project）

- 可选。**每条任务至多一个项目**。格式：`+项目名`。
- `+` 前必须是行首或空白字符，因此 `C++`、`A+B` 等写法不会产生误判。
- 若描述主体中出现多个 `+名称`，仅第一个识别为项目，其余视为普通描述文本。
- 位置不限，建议放在描述之后、标签之前。
- **每条任务独立声明自己的项目，不支持跨任务继承。**

#### 7.2.5 标签（Tag）

- 可选，零至多个。格式：`#标签名`。
- `#` 前必须是行首或空白字符。
- 首字符不得为数字（见上方字符集说明）。
- 支持中英文混排，如 `#紧急`、`#waiting`、`#等回复`。
- 建议放在主行尾部，数量控制在 0–2 个。

### 7.3 续行 (Continuation Lines)

- 缩进行属于最近的上一个任务锚点，**即使中间隔着空白行**（备注内空行，见 §7.1）。
- 续行内部**不解析** `+` 和 `#` 为项目或标签，也不识别优先级与日期（避免误触）。
- 续行支持任意文本，包括 Markdown 列表、代码块、URL 等。
- 解析器应当**原样保留**续行内容（含缩进），以便保留代码块等依赖缩进的结构；展示层可以去除公共缩进，但解析层不得强制左对齐。
- 续行中唯一具有结构化语义的是**时间戳行**（整行匹配"日期 + 关键字"），见 §7.4；其余续行一律为自由文本。

### 7.4 时间戳行 (Timestamp Lines)

任务的**创建时间**与**完成时间**以时间戳行的形式记录在续行中。到期（截止）时间属于任务的定义，保留在主行日期位（§7.2.2）；创建与完成属于任务的经历，作为日志型事实追加在续行。主行裸日期与续行时间戳行形态不同，任何日期的语义均可由其写法局部判定。

#### 7.4.1 语法

```bnf
timestamp_line ::= indent date SP keyword [trailing_ws]
indent         ::= 1*( SP | TAB )
keyword        ::= 创建关键字 | 完成关键字        ; 见 §7.4.2 关键字字典
```

- 时间戳行必须**整行匹配**：去掉缩进与行尾空白后，除日期与关键字外不得含有任何其他字符。含其他文字的续行（如 `2026-08-05 完成初稿`、`创建于 2026-08-05`）是普通备注，解析器不得识别为时间戳行。
- 日期必须严格符合 `YYYY-MM-DD` 且为合法日期（与主行日期位同规则）。
- 时间戳行内不解析优先级、`+项目`、`#标签` 等其他元数据。

#### 7.4.2 关键字字典 (Keyword Dictionary)

关键字按语义类型组织为字典，作为多语言适配的扩展点：

| 语义类型 | 规范形式 | 英文别名    |
| -------- | -------- | ----------- |
| 创建     | `创建`   | `created`   |
| 完成     | `完成`   | `completed` |

- 解析器**必须**识别字典中的全部关键字；英文别名**大小写不敏感**（`Created`、`CREATED` 均识别）。
- 书写工具**应当**使用规范形式（zh-CN 关键字），以保证文件风格统一。
- 新增语言时，只需在字典中为各语义类型追加关键字，语法本身不变。字典之外的关键字不识别，相应行按普通备注处理，解析器不得报错。

#### 7.4.3 语义

- **创建时间戳**：每个任务应当至多一条。工具创建任务时应当将其写为**第一条续行**；状态流转不得修改或删除它。出现多条时取**第一条**为创建时间，其余按普通备注保留。
- **完成时间戳**：任务每次进入 `DONE` 时，工具应当在续行**末尾追加**一条。任务被重开（移回 `DOING`/`WAIT`）时保留既有完成时间戳；再次完成时追加新行。取**最后一条**为完成时间，其余构成完成历史。
- 解析器应当将时间戳提取为结构化字段（如 `createdAt` / `completedAt`），同时按 §7.3 原样保留其所在续行，保证写出无损。
- 两种时间戳均可选：手写任务不含时间戳行完全合法。

## 8. 完整示例 (Example)

```stanza
# DOING

(A) 2026-08-07 完成登录模块的单元测试 +Apollo #紧急
    2026-08-05 创建
    先跑通现有测试用例
    再补充边界情况

    测试数据在共享盘的 testdata 目录

(B) 2026-08-07 预约周五下午的牙医 +生活
    2026-08-06 创建
    记得带医保卡

整理《重构》读书笔记 +学习
    重点看第 3、6 章
    摘抄代码坏味道清单

# WAIT

2026-08-05 等设计组回复新版图标 +Apollo
    2026-08-04 创建
    上周已提需求，预计本周五交付

# DONE

2026-08-05 修复列表页滚动卡顿的问题 +Apollo
    2026-08-04 创建
    2026-08-06 已合入主干，随 2.3 版本发布
    2026-08-06 完成

2026-08-03 更新部署文档 +运维
    已同步到团队 Wiki
    2026-08-03 完成

# DELETE

调研第三方推送服务 +Apollo
    2026-08-01 创建
    报价超出预算，改用自建方案
```

说明：第一个任务的两段备注之间有一个空白行。根据 §7.1 规则 3，该空白行属于备注内容，**不**分割任务。DONE 区块中 `2026-08-06 已合入主干，随 2.3 版本发布` 含其他文字，是普通备注；其后的 `2026-08-06 完成` 整行匹配，是完成时间戳行（§7.4）。时间戳行可选：第二个 DONE 任务没有创建时间戳，依然合法。

## 9. 状态流转约定（推荐） (State Transitions)

以下约定面向写入工具（编辑器、CLI、插件），均为"应当"级别，不影响文件本身的合法性：

- **新增任务**：追加到目标区块末尾；应当写入创建时间戳行（§7.4），作为第一条续行。
- **完成任务**：将整个任务段落（含全部续行）从 `DOING`/`WAIT` 移至 `DONE`，移除优先级前缀；应当在续行末尾追加一条完成时间戳行（§7.4）。
- **废弃任务**：将任务段落移至 `DELETE`。`DELETE` 是回收站语义，便于误删恢复。
- **恢复任务**：从 `DELETE` 移回目标区块，元数据保持不变。
- **重开任务**：从 `DONE` 移回 `DOING`/`WAIT`，元数据与既有时间戳行保持不变；再次完成时追加新的完成时间戳行（§7.4.3）。
- 工具在流转过程中不得自动修改主行日期（截止日期）与既有续行内容；用户需要调整截止日期时手动编辑即可。

## 10. 解析器实现指南 (Implementation Guide)

### 10.1 词法规则（正则参考）

```regex
# 区块标题（状态名大小写不敏感）
(?i)^# (DOING|WAIT|DONE|DELETE)[ \t]*$

# 主行整体：优先级 + 截止日期 + 描述主体
^(?:\(([A-Z])\) )?(?:(\d{4}-\d{2}-\d{2}) )?(.*)$

# 项目（+ 前必须是行首或空白字符）
(?<!\S)\+[\p{L}\p{N}][\p{L}\p{N}_-]*

# 标签（# 前必须是行首或空白字符，首字符必须是字母）
(?<!\S)#\p{L}[\p{L}\p{N}_-]*

# 时间戳行（续行中整行匹配；关键字取自 §7.4.2 字典，英文大小写不敏感）
(?i)^[ \t]*(\d{4}-\d{2}-\d{2}) (创建|完成|created|completed)[ \t]*$
```

说明：

- 区块标题的状态名大小写不敏感；解析后应统一转为大写规范形式，写出文件时使用大写。
- `\p{L}` 匹配任意 Unicode 字母（含中日韩表意文字），`\p{N}` 匹配任意数字。需要支持 Unicode 属性类的正则引擎（PCRE2、Java、.NET、Python `regex` 模块、JavaScript `u` 标志等）。
- 若引擎不支持 `\p{...}`（如 Python 标准库 `re`），可使用近似写法：`\p{L}` → `[^\W\d_]`，`[\p{L}\p{N}]` → `[^\W_]`，`[\p{L}\p{N}_-]` → `[\w-]`。
- 时间戳行的关键字选择项应当从 §7.4.2 关键字字典生成；新增语言时扩充字典即可，模式结构不变。

### 10.2 解析算法（伪代码）

```python
BLOCK_RE  = re.compile(r'^# (DOING|WAIT|DONE|DELETE)[ \t]*$', re.IGNORECASE)
HEADER_RE = re.compile(r'^(?:\(([A-Z])\) )?(?:(\d{4}-\d{2}-\d{2}) )?(.*)$')

def parse_stanza(text):
    blocks = []
    block = None    # 当前状态区块
    task = None     # 当前任务锚点
    blanks = 0      # 已遇到、归属未定的连续空白行数

    for line in text.splitlines():
        m = BLOCK_RE.match(line)
        if m:                                   # 区块标题
            block = Block(state=m.group(1).upper())  # 统一为大写规范形式
            blocks.append(block)
            task, blanks = None, 0
        elif line.strip() == '':                # 空白行：暂存，归属待定
            blanks += 1
        elif line[0] in ' \t':                  # 缩进行：续行
            if task is not None:
                task.notes.extend([''] * blanks)  # 备注内空行保留
                task.notes.append(line)           # 原样保留缩进
                blanks = 0
            # 否则为孤立续行：忽略（可警告）
        else:                                   # 无缩进行：一律开启新任务
            if block is None:
                continue                        # 首个区块标题之前的内容：忽略或报错
            task = parse_header(line)
            block.tasks.append(task)
            blanks = 0

    return merge_duplicate_blocks(blocks)

def parse_header(line):
    m = HEADER_RE.match(line)
    priority, due, body = m.groups()
    project = first_match(PROJECT_RE, body)     # 至多取第一个
    tags = TAG_RE.findall(body)                 # 零至多个
    description = strip_matches(body, project, tags)
    return Task(priority, due, description, project, tags, notes=[])
```

### 10.3 边界情况与测试用例

| 2   | 任务 → 空白行 → 无缩进行             | 两个任务；空白行仅作分隔符                           |

### 10.4 给 AI 的提示词模板

若需让 AI 生成插件或解析器，可使用以下提示词：

> 请根据 Stanza RFC 规范实现一个 [语言] 解析器/插件。核心要求：
> 1. 支持四种状态区块：DOING、WAIT、DONE、DELETE；状态名大小写不敏感（拼写必须正确），同名区块逻辑合并。
> 2. 每条无缩进的非空白行都开启一个新任务（换行即分隔）；任务之间的空白行仅作视觉分隔。
> 3. 空白行后接缩进行时，空白行计入上一任务的备注（备注内空行）。
> 4. 主行依次解析优先级 `(A)`、截止日期 `YYYY-MM-DD`、描述主体；描述中内嵌至多一个 `+项目` 与零至多个 `#标签`，`+`/`#` 前必须是行首或空白字符，标签首字符不得为数字。
> 5. 续行原样保留（含缩进），不解析任何元数据；无锚点的孤立续行忽略。
> 6. 输出结构化数据（JSON/对象列表），包含：状态、优先级、截止日期、描述、项目、标签列表、备注列表。

## 11. 与 TODO.txt 的关系

Stanza 是 TODO.txt 的**方言与扩展**，而非替代。主要差异：

| 特性     | TODO.txt                | Stanza                             |
| -------- | ----------------------- | ---------------------------------- |
| 任务边界 | 换行符 `\n`             | 换行符（每条无缩进行一个任务）        |
| 任务备注 | 不支持多行              | 缩进续行，备注内可含空行           |
| 状态管理 | `x` 前缀 + 归档文件     | 状态区块（DOING/WAIT/DONE/DELETE） |
| 标签符号 | `@context` + `+project` | `#标签` + `+项目`                  |
| 行首日期 | 创建日期                | 截止日期                          |
| 完成日期 | 行首第二个日期          | 记录在续行（推荐约定，见 §9）      |

Stanza 文件可被降级阅读为普通 TODO.txt（忽略缩进续行和区块标题即可），但完整功能需专用工具支持。
